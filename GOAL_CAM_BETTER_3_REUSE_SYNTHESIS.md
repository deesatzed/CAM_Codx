# CAM Better Evidence Goal 3: Warm Reuse and Net-New Proof

This is the third executable contract in the CAM Better Evidence Program. The
controlling plan is
`/Volumes/WS4TB/waswikiT/repos2mine/CAM_KnowledgeSourceBench/docs/plans/2026-08-19-cam-better-evidence-program.md`.
The machine-readable continuation state is
`/Volumes/WS4TB/waswikiT/repos2mine/CAM_KnowledgeSourceBench/PROGRAM_STATUS.json`.

Run this goal only when the status file names
`GOAL_CAM_BETTER_3_REUSE_SYNTHESIS.md` as `active_goal` and the committed Goal
2 gate is valid. Use `executing-plans`, `cam-codx-session`, test-driven
development, and `verification-before-completion`.

/goal

OUTCOME: Complete Tasks 14-20 of the controlling plan and determine whether
CAM's mined knowledge provides measurable warm-reuse economics, portable
read-only value, correct outcome memory, least-cost source routing, and a
verified net-new multi-source build in the strongest task class supported by
Goals 1-2. Close the program with a claim-by-claim audit that may conclude CAM
wins, ties, loses, or has no demonstrated advantage.

PROOF OF DONE:

1. A portable-knowledge-package specification and tested manifest schema bind
   database digest/integrity, schema/runtime and retrieval identities, source
   revisions, licenses/privacy, config/profile metadata, path remapping,
   unavailable sources, and explicit secret exclusion.
2. E4 measures cold mining and warm retrieval/build use at counts 1, 5, 10,
   and 25, including provider spend, tokens, wall time, files reopened,
   retrieval latency, outcome correctness, and a calculated break-even point
   or explicit no-break-even result.
3. E5 verifies fresh and portable temporary CAM homes and, when available, a
   separate MacBook. It checks verdict/evidence identity, unavailable-path
   honesty, secret absence, provider/mining-call absence, and equivalent
   read-only assessment where source access is not required. Any unavailable
   physical-machine proof is recorded as blocked, not silently simulated.
4. E6 includes one verified outcome, one failed outcome, and one hypothetical
   candidate. CAM recommends only the verified result positively, warns about
   the failure, and labels the hypothesis unverified.
5. E7 preregisters and scores routes for current public API, local invariant,
   prior failure, local-plus-current, stale CAM evidence, offline CAM
   sufficiency, and neither-source-sufficient cases. Metrics include route
   accuracy, false sufficiency, unnecessary external calls/mining/source
   reads, cost, and final executable outcome.
6. E8 selects its final task only from the strongest task class established by
   Goals 1-2 and proves the required combination is absent from every donor
   before generation. Base, CAM, Context7, raw-source, and CAM+Context7 arms
   use equal frozen controls and hidden tests.
7. E8 reports quality, safety, context size, cost, reliability, provenance,
   and novelty. The net-new claim requires complementary multi-source
   obligations and cannot be satisfied by renaming or directly copying one
   donor artifact.
8. The verified E8 outcome, if any, is recorded through CAM managed-run and a
   fresh read-only CAM_Codx assessment recalls only active verified positive
   evidence while retaining failures and hypotheses distinctly.
9. `docs/reports/<date>-cam-better-final-report.md` and
   `artifacts/program-final-gate.json` mark every claim-ladder rung `passed`,
   `failed`, `blocked`, or `not tested` and cite exact receipts, commits,
   branches, costs, limitations, rollback notes, and dirty-state truth.
10. Focused and full affected-repository suites, manifest/receipt validation,
    generated artifacts, installation/portability checks, and
    `git diff --check` pass, except explicitly documented unrelated baselines.
11. Every repository is committed separately, `PROGRAM_STATUS.json` is
    `complete` or names an allowed externally blocked proof precisely, and no
    use of “better” omits the task class, comparator, metric, and evidence.

  `/Volumes/WS4TB/waswikiT/repos2mine/CAM_KnowledgeSourceBench`.

- Follow Tasks 14-20 and E4-E8 in the controlling plan.
- Add only the minimum portable-package, accounting, routing, fixture,
  reporting, and managed-run composition required by these experiments.
- Choose the final target only after Goals 1-2 identify CAM's supported task
  class. Use a new isolated target and record its initial/final commits.
- Source repositories remain read-only at pinned revisions. Reuse code only
  within verified license boundaries and preserve clean-room distinctions.
- Canonical state, production services, model promotion, and deployment remain
  outside scope unless separately and explicitly authorized.

CONSTRAINTS:

- Fail closed unless the status ledger activates Goal 3 and valid Goal 1 and
  Goal 2 gates are committed and digest-verifiable.
- Read the master plan, ledger, both prior gates/reports, this goal, and truth
  files before work. Resume from ledger/receipts rather than conversation.
- Do not begin with a preferred showpiece. Select E8 only from measured prior
  strengths and preregister its novelty and source-necessity tests.
- Warm-use economics count cold mining cost and correctness. Do not claim cost
  savings by excluding setup cost, using a weaker outcome, or ignoring failed
  attempts.
- Portability packages must exclude `.env`, credentials, API keys, raw private
  data, machine-specific secrets, and mutable or ambiguous identities.
- Context7, CAM, raw-source, CAM+Context7, and base routes remain isolated
  until their fixed arm packets are frozen. Do not repair an arm using another
  arm's evidence.
- Use deterministic hidden tests rather than an LLM judge. No claim may rest
  on retrieval prose, similarity, row count, or model self-assessment alone.
- Preserve failures, limitations, negative outcomes, and no-break-even
  results. Do not weaken tests or rewrite prior goal evidence.
- Provider spending, live mining, canonical database/config mutation,
  model/profile change, target mutation outside the isolated E8 contract,
  destructive action, and deployment require their exact approvals.

AUTONOMOUS EXECUTION POLICY:

- Continue autonomously through specs, schemas, tests, disposable homes,
  offline accounting, local routing evaluation, isolated target construction,
  review, documentation, and scoped commits.
- Use one bounded authorization per exact paid/mining/mutating phase rather
  than asking for approval per command. Never infer one approval covers a
  different model, task, database, target, cost, or phase.
- Ordinary failures are evidence and diagnosis work. Continue while a safe
  in-scope measurement or mitigation remains.
- After each task, update `PROGRAM_STATUS.json` and `PROGRESS.md`, validate,
  and commit before proceeding.

SAFETY / PROVENANCE:

- Resolve and record exact code, database, config, profile, source, target,
  package, evaluator, provider, model, and receipt identities before each
  consequential phase.
- Use disposable CAM homes and databases first. Verify SQLite integrity and
  hashes before and after, and prove no unintended canonical mutation.
- Preserve source receipts, licenses, privacy boundaries, direct/analogy/
  hypothesis labels, selected/rejected decisions, landing maps, tests, and
  rollback evidence.
- Do not transmit secrets, hidden tests, private source, private corpus rows,
  credentials, or unnecessary personal data to providers or subagents.
- Do not execute code merely because it was mined or recalled. Inspect,
  select, land cleanly, test, and record only verified outcomes positively.
- Fixture, local-machine, and synthetic evidence must remain labeled and may
  not be called production readiness, general safety, or universal capability.

ITERATION:

1. Run the recovery checklist and validate both prior gates, the status
   ledger, repository identities, and the exact Goal 3 starting claims.
2. Execute Task 14 test-first: specify and validate the portable package
   before copying any corpus or configuration material.
3. Run E4 accounting at 1/5/10/25 uses and E5 fresh-versus-portable proof using
   temporary CAM homes. Preserve a physical-machine block if the MacBook is
   unavailable.
4. Run E6 outcome memory and E7 least-cost routing with preregistered cases and
   deterministic scoring. Diagnose losses without changing cases after seeing
   results.
5. Select and freeze E8 only after the earlier Goal 3 results. Prove novelty,
   source necessity, licenses, privacy, evaluator, arms, model, and maximum
   cost before any paid or mutating execution.
6. Stop for exact authorizations where required, then run arms sequentially,
   score them identically, record any verified outcome through managed-run,
   and test later recall.
7. Audit every claim-ladder rung, perform skeptical evidence review, remediate
   blocking defects, commit final artifacts, and close the status ledger.

STOP:

Pause and report the exact blocker only if:

- the prior goal gates or status ledger are missing, invalid, or inconsistent;
- credentials, API access, provider spend, live mining, canonical mutation,
  model/profile change, target authorization, destructive action, license or
  privacy rights, deployment, or production mutation is required and not
  authorized;
- no supported task class exists from Goals 1-2 from which E8 can be selected;
- the final target's ownership, license, privacy, or hidden-evaluator boundary
  is materially uncertain;
- the same blocking condition remains after three distinct documented repair
  strategies;
- required verification cannot execute and no safe local, fixture,
  disposable, or read-only alternative can establish the evidence; or
- continuing would hide cost, weaken safety/provenance, discard user changes,
  overwrite negative evidence, or expand beyond Goal 3.

COMPLETE:

Mark this goal and program complete only when Tasks 14-20 have committed
receipts, E4-E8 each have an honest pass/fail/block result, break-even is
calculated or rejected, portability and routing are measured, E8 has
hidden-test/safety/provenance/novelty evidence or a legitimate explicit block,
the final audit classifies every claim-ladder rung, all required verification
passes except recorded unrelated baselines, and the status ledger contains no
unsupported success. A final conclusion that CAM ties, loses, or has no
demonstrated advantage is valid completion when the evidence program itself is
complete.
